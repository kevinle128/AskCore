## Overview

Priority P1. Write `design.md` for the trust prompt, the `/trust` command, the untrusted notice and the settings diagnostics notice. The exit of this phase is the user's explicit approval of that file. No Go code.

This screen is a startup gate for project files. It is not a tool-approval popup, so D3 (`roadmap.md:53`) stays as decided.

## Key insights

- A dialog takes the prompt pane slot and keeps the draft (skill, "Read first"). The prompt shows before the first `session/new`, so the block pane is empty.
- The decision applies to the next session. `/trust` must say so in its result text.
- Session-only choices travel as the `session/new` override (plan S15). The design picks which of Pi's five options Ask shows.
- When `_ask/trust/state` answers "not available" (old leader), the TUI shows nothing (plan, wire compatibility).

## Requirements

1. Create `plans/261103-2158-h6a-settings-trust/design.md` with the skill frontmatter (`design-status: draft`) and the eleven sections in skill order: Outcome, Non-goals, Placement, Sketches, States and transitions, Keys and focus, Limited space and resize, Text and width, Style intent, Acceptance criteria, Open questions.
2. Sketches at 80x24 for each state; 120x40 only where the layout changes; a 40-column case for long paths. States at least:
   - startup prompt (folder with gated files, no saved decision), with the canonical root and the gated file list;
   - prompt with a long path and a long gated list (truncation);
   - after "Trust": session starts, result row text;
   - after "Do not trust": session starts, untrusted notice;
   - untrusted notice when the decision came from `--no-approve`, `defaultProjectTrust: never`, or a saved `false`;
   - corrupt `trust.json` warning (no prompt, untrusted);
   - `/trust` selector showing the current entry and whether it is inherited from an ancestor;
   - settings diagnostics notice (for example a denied project key);
   - Escape or Ctrl+C on the prompt (cancel means untrusted for this session, nothing saved).
3. Options to decide in the design, with a recommendation: Trust, Trust parent folder, Trust this session only, Do not trust, Do not trust this session only.
4. Render all sketches as one HTML preview from one script under `plans/261103-2158-h6a-settings-trust/artifacts/`, check it with a headless browser screenshot, and verify widths with the `verify-widths.py` approach.
5. Acceptance criteria in the form "At <size>, after <input>, the screen shows <text> in <region>."
6. Stop and ask the user for approval. Record approver and date only after explicit approval of this file.
