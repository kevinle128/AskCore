Agent loop, từng bước một

Trang này dành cho người chưa biết gì về agent loop. Bạn sẽ thấy vòng lặp làm gì, sáu stage của một lượt, và cách các hook cắm vào từng stage. Mọi chi tiết lấy từ code thật của AskCore.

Ý tưởng gốc

Model chỉ biết nói. Agent loop giúp nó làm việc.

Một LLM nhận văn bản và trả văn bản. Nó không tự đọc file hay chạy lệnh. Thay vào đó, nó có thể xin chạy một công cụ (tool), ví dụ "đọc file README.md". Agent loop là đoạn code đứng giữa: nó gửi yêu cầu cho model, chạy tool mà model xin, đưa kết quả lại cho model, rồi lặp lại cho đến khi model trả lời xong. Mẫu này gọi là ReAct: Reason + Act.

ReasonModel đọc toàn bộ hội thoại và quyết định: trả lời luôn, hay gọi tool.stage reason
ActLoop chạy các tool mà model đã xin, có thể song song.stage act
ObserveKết quả tool được thêm vào hội thoại, để lần sau model thấy.stage observe

AskCore bổ sung ba stage nữa quanh lõi đó: steer (nhận input), prepare (chuẩn bị request) và decide (quyết định chạy tiếp hay dừng). Sáu stage này tạo thành một turn.

Một turn

Sáu stage, chạy theo thứ tự cố định

Bấm vào một stage để xem nó làm gì. Số "hook" trên mỗi ô cho biết có bao nhiêu điểm để code bên ngoài can thiệp vào stage đó. Mũi tên đứt nét là đường quay lại khi model còn gọi tool.

    Ngoài turn

    Hai vòng lặp lồng nhau

    Hàm loop.run() (loop_run.go:311) chạy turn này đến turn khác. Vòng trong lặp khi còn tool result hoặc tin nhắn steering. Vòng ngoài chạy khi agent sắp dừng: nó xem hàng đợi follow-up. Có tin mới thì mở một cycle mới.

    flowchart TD
  S(["agent_start"]) --> T["Chạy một turn: steer, prepare, reason, act, observe, decide"]
  T --> F{"decide trả gì?"}
  F -- "flowNextTurn: còn tool hoặc steering" --> T
  F -- "flowEndRun: lỗi, abort, hoặc hook trả End" --> E(["agent_end"])
  F -- "flowIdle: hết việc" --> Q{"Hàng đợi có follow-up?"}
  Q -- "Có" --> C["Đóng cycle cũ, mở cycle mới"] --> T
  Q -- "Không" --> K{"Hook đã xin Continue?"}
  K -- "Có, chưa quá 3 lần rỗng" --> T
  K -- "Không" --> E

    Giới hạn 3 lần (maxEmptyContinuations, loop_run.go:20) chặn trường hợp một hook luôn trả Continue, gây lặp vô hạn.

    Hook

    Hook cắm vào stage nào

    Hook là hàm bạn đăng ký vào pipeline.Registry (internal/pipeline/registry.go). Loop gọi nó tại một điểm cố định. Nhờ vậy bạn thêm hành vi (chặn lệnh nguy hiểm, đổi model, retry khi lỗi) mà không viết vòng lặp thứ hai. Có 9 điểm, phân bố như sau:

    Hai kiểu hook

    Around: lớp hành tây

    Bảy điểm dùng kiểu này. Handler nhận input và một hàm next. Nó có thể sửa input, gọi next để chuyển cho lớp trong, rồi sửa kết quả. Nó cũng có thể không gọi next và tự trả kết quả, ví dụ để chặn.

    Handler của ứng dụng chạy trước handler riêng của từng Agent (pipeline.Scoped). Mỗi handler chỉ được gọi next một lần.

    Decider: lá phiếu

    Hai điểm CompleteStep và StopTurn dùng kiểu này. Mỗi handler trả một quyết định. Loop lấy quyết định mạnh nhất (decisions.go:27).

    Proceed
    Continue
    End

    yếu → mạnh

    Proceed: theo lịch bình thường. Đây là mặc định.
    Continue: bảo đảm có thêm một request tới model, kể cả khi không còn việc.
    End: kết thúc run sau turn_end, không lấy gì từ hàng đợi.

    Một handler nói End là đủ để dừng, dù các handler khác nói Continue.

    Đăng ký một hook trong code

    Mỗi hàm On… trả về một hàm gỡ đăng ký. Đoạn dưới là ví dụ minh họa, không có trong repo:

    reg := pipeline.NewRegistry()

// Around: chặn mọi lệnh có "rm -rf" trước khi tool chạy.
stop := reg.OnBeforeTool(func(ctx context.Context, in pipeline.ToolCallInfo,
	next pipeline.Next[pipeline.ToolCallInfo, *pipeline.BeforeToolCallResult],
) (*pipeline.BeforeToolCallResult, error) {
	if bytes.Contains(in.Args, []byte("rm -rf")) {
		return &pipeline.BeforeToolCallResult{Block: true, Reason: "lệnh nguy hiểm"}, nil
	}
	return next(ctx, in) // chuyển cho lớp trong
})
defer stop() // gỡ hook

// Decider: dừng run khi đã có quá 40 tin nhắn mới.
reg.OnCompleteStep(func(ctx context.Context, t pipeline.Turn) (pipeline.TurnDecision, error) {
	if len(t.NewMessages) > 40 {
		return pipeline.End, nil
	}
	return pipeline.Proceed, nil
})

    Ví dụ thật trong repo: Agent tự đăng ký một handler OnPrepareRequest để chiếu context vào mỗi request (internal/agent/agent.go:535).

    Từ vựng

    Bốn đơn vị công việc

    run ⊃ cycle ⊃ turn ⊃ attempt

    runMột lần agent chạy, từ agent_start đến agent_end.loop.run()
    cycleCông việc cho một nhóm input. Follow-up mới mở cycle mới.openCycle / closeCycle
    turnMột vòng sáu stage. Tạo ra đúng một assistant message.runTurn()
    attemptMột lần gọi model. Khi retry, một turn có nhiều attempt.streamAttempt()
    Quy tắc nên nhớ

    Ba bất biến

    1. Ghi log trước, phát event sau. Session log là nguồn sự thật duy nhất (loop_run.go:235).
    2. Prepare phải thành công thì input mới vào lịch sử. Nếu prepare lỗi, input đã stage không được lưu.
    3. Muốn thêm hành vi thì đăng ký hook. Không thêm một vòng lặp thứ hai bên cạnh loop.
