## 16. Open questions resolved

Q1. What happened to the `glob` and `think` tools and the 0.12.0 print flags?
- `glob` and `think` are gone. The factory switch in `C:core/tools/index.ts:150-180` creates `read`, `bash`, `edit`, `write`, `grep`, `find`, `ls` and throws `Unknown tool name` for anything else. CL 0.34.0 (lines in the early range) lists the seven current tools. Commit `186169a82` ("add read-only exploration tools (grep, find, ls) and --tools flag") added the read-only trio. The git history in this checkout does not show the removal commit and the changelog never records it, so the exact version is "absent by 0.34.0, removal not recorded".
- The 0.12.0 flags are gone. `C:cli/args.ts:167-168` handles only `--print`/`-p`; `--mode` is at `:95-98`, `--thinking <level>` at `:157`; the help text (`:294-295`) lists no `-P`, `--print-turn`, `--no-markdown` or `--thinking-<level>`. A search of git history for `--print-turn` and `--no-markdown` returned nothing, so no removal commit is available. Unknown long flags now land in `unknownFlags` (`args.ts:55-56,240-245`) for extensions, so `--print-turn` is silently treated as an extension flag, not an error.

Q2. Anthropic OAuth (removed 0.40.1, restored 0.41.0): active now?
- Yes. CL:4186-4197 records "Removed: Anthropic OAuth support (`/login`)" in 0.40.1 and "Anthropic OAuth support is back!" in 0.41.0, both dated 2026-01-09, with no reason. In source, `AI:providers/anthropic.ts:3,50-53` wires `lazyOAuth({ load: loadAnthropicOAuth })`, `AI:auth/oauth/load.ts:33-35` loads `anthropicOAuth`, and `AI:auth/oauth/anthropic.ts:229-230` exports it as "Anthropic (Claude Pro/Max)". The legal question in H-AUTH-11 stays open.

Q3. Gmail and Calendar OAuth (0.10.0)?
- Not implemented anywhere. The only occurrence of "Gmail" outside a copyright line in `C:utils/ansi.ts:8` is `CL:5978` ("OAuth integration for Gmail and Google Calendar access", 0.10.0). There is no source, no later changelog line, and no doc. Treat it as removed without a record.

Q4. The `mom` package?
- Removed. Commit `0ed0d4343` (2026-04-30, "remove mom and pods packages") deletes it; the commit body points to `earendil-works/pi-chat`. `packages/` today has 14 directories and no `mom` (`ls packages`). The 0.20.1 note said the skills API was exported for `mom`. Out of scope for Ask.

Q5. Session-file locking?
- None in the shipping `SessionManager`. Writers are `openSync(file, "wx")` at `C:core/session-manager.ts:1177`, `appendFileSync` at `:1187`, and the fork writer at `:1856,1861`; there is no lock call in that file. `proper-lockfile` is imported by `package-manager-cli.ts:14`, `auth-storage.ts:9` (shipping), and by `experimental/server.ts:25`, `experimental/session-worker.ts:28`, `experimental/micro/sessions.ts:4` (experimental). So Pi relies on one process per session file. Two processes resuming the same file would interleave lines. Ask needs its own per-session lock.

Q6. Retry jitter?
- Absent. `AI:utils/retry.ts:122-126` computes `min(baseDelayMs * 2^(attempt-1), maxAgentDelayMs ?? 60000)` with no random term; the call site is `:218`. The doc comment at `:114` says "before jitter", which is stale. `grep -i jitter` over `ai`, `agent` and `coding-agent` `src` finds only that comment. Whether Go adds jitter is a design choice (Q2 below).

Conflicts checked at source:
- Retry defaults: types and comments at `C:core/settings-manager.ts:48-50`; getters at `:1001-1003`. Both are right.
- Compaction threshold: `C:core/compaction/compaction.ts:269` (`contextTokens > contextWindow - settings.reserveTokens`).
- Built-in slash commands: 24 in `C:core/slash-commands.ts:19-43`; `/llama` is not among them (lane F listed 25 by including it).
- Steering vs tool batch: 0.25.0 changelog says a queued message skips remaining tools; current loop polls steering only after the batch (`A:agent-loop.ts:284-300`) and CL 0.58.4 fixed the skip. Current behavior wins.
- Print exit code: text mode sets exit 1 on `error` or `aborted` (`C:modes/print-mode.ts:145-148`); JSON mode does not (DI§1).
