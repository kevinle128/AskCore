## Actual side effects and public contracts

Admitted messages remain outside the session message projection until request preparation succeeds.
Preparation errors publish the D20 tail without saving input or the error message.
Each retry prepares from committed history, uses captured provider policy, and keeps the input once.
The five default retries use delays of 500, 1000, 2000, 4000 and 8000 ms with no jitter.
A Retry-After above the policy cap stops retrying.
A billing method, profile or billing hint change stops adapter dispatch, while a refreshed token with the same binding is allowed.
The retry policy fields, registration option, RequireBinding, retry records, retry codecs and Wait seam are intended contract changes.
ExecuteModel now returns a settled ModelOutcome; its request remains frozen and its context covers stream consumption.
Aborted nonblank content replays, unsigned aborted thinking becomes text, and failed error messages remain outside provider replay.
Plain stream registration now returns PolicyOnly preparation metadata, and the driver clears opts.Prepared at the stream boundary.
Re-registration clears a stale preparer.
No new dependency or package boundary was introduced.
