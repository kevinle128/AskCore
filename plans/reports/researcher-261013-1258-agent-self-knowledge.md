# Agent self-knowledge and automated docs (research, 2026-10-13)

Bottom line: every harness uses the same three layers. (1) A small always-on prompt block with facts and pointers. (2) On-demand docs the model reads only when the question is about the harness itself. (3) Reference docs generated from code, with a CI check to stop drift. Ask should copy this layering. Do not paste docs into the system prompt.

## A. Claude Code

| Mechanism | What it does | Source |
|---|---|---|
| Docs map | `https://code.claude.com/docs/en/claude_code_docs_map.md` is an index of about 150 pages. It says it is auto-generated by GitHub Actions and points to `https://code.claude.com/docs/llms.txt`. Every page is also served as `.md`. | code.claude.com/docs/en/claude_code_docs_map.md (fetched) |
| claude-code-guide subagent | Built-in, runs on Haiku. Used when the user asks about Claude Code features, hooks, slash commands, MCP, settings, shortcuts, the Agent SDK or the API. The main model delegates to it and does not answer from memory. The guide prompt says: reuse a running guide agent (SendMessage) instead of spawning a new one. | code.claude.com/docs/en/sub-agents; Piebald `agent-prompt-claude-code-guide.md` |
| Live-docs source list | The guide's prompt carries a data block of WebFetch URLs. The docs map is the primary index. Fetch the `.md` URL, link the user to the URL without `.md`. A bundled `references/` folder is the offline fallback. | Piebald `data-claude-code-live-documentation-sources.md` |
| Other self-config agents | `statusline-setup` (Sonnet, runs on `/statusline`, about 4.8k-token prompt) and `Explore`, `Plan`, `general-purpose`. Each is a subagent with its own prompt and tools. | sub-agents doc; Piebald `agent-prompt-status-line-setup.md` |
| Environment block | A short block in the system prompt: working dir, git repo yes/no, platform, shell, OS version, model name and exact model ID, knowledge cutoff, date. The git status snapshot arrives as a separate "context" message and is marked as a snapshot. | Observed in this session's own prompt; I did not find a public doc that specifies it |
| Feature lists in the prompt | The skill list (name plus description), the agent types (name plus when to use), and deferred tool names are listed in system reminders. Deferred tools (MCP, rare tools) show only names. The model loads their schemas through a `ToolSearch` tool. MCP servers add "server instructions". | Observed in this session; Piebald `system-prompt-chrome-browser-mcp-tools.md` shows the ToolSearch batching rule |
| Progressive disclosure for skills | Level 1: `name` and `description` of every skill are in the prompt. Level 2: the model reads the full `SKILL.md` when it decides the skill is relevant. Level 3: bundled files are read only when needed. The listing truncates `description` plus `when_to_use` at 1,536 characters. `disable-model-invocation: true` removes the skill from the listing. | anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills; code.claude.com/docs/en/skills |
| Bundled skills | Prompt-only skills that teach the harness: `/doctor`, `/claude-api`, `/debug`, `/verify`, `/run` and others. Settings can disable them (`disableBundledSkills`). Config helpers such as update-config and keybindings-help exist in this session's skill list, but I did not find a doc page for them. | skills doc; session observation |

Caveat: Piebald files are extracted from the shipped binary by a third party. They are reliable for wording, but they track a specific version.

## B. Pi (badlogic/pi-mono)

File: `packages/coding-agent/src/core/system-prompt.ts`, in `buildSystemPromptSections` (about line 94). The URL I fetched was `https://raw.githubusercontent.com/badlogic/pi-mono/main/packages/coding-agent/src/core/system-prompt.ts`. Wording as fetched (the fetch tool returned a verbatim quote; I did not diff it against a local checkout):

```
Pi documentation (read only when the user asks about pi itself, its SDK, extensions, themes, skills, or TUI):
- Main documentation: ${getReadmePath()}
- Additional docs: ${getDocsPath()}
- Examples: ${getExamplesPath()} (extensions, custom tools, SDK)
- When reading pi docs or examples, resolve docs/... under Additional docs and examples/... under Examples, not the current working directory
- When asked about: extensions (docs/extensions.md, examples/extensions/), themes (docs/themes.md), skills (docs/skills.md), prompt templates (docs/prompt-templates.md), TUI components (docs/tui.md), keybindings (docs/keybindings.md), SDK integrations (docs/sdk.md), custom providers (docs/custom-provider.md), adding models (docs/models.md), pi packages (docs/packages.md), environment variables (docs/environment-variables.md), MCP servers (docs/mcp.md), codemode scripts ... (docs/codemode.md)
- When working on pi topics, read the docs and examples, and follow .md cross-references before implementing
- Always read pi .md files completely and follow links to related docs (e.g., tui.md for TUI API details)
```

Key design points:
- The paths are computed at runtime (`getReadmePath()`, `getDocsPath()`, `getExamplesPath()`), so they point at the docs shipped with the installed package. The docs always match the installed version, with no network.
- There is no subagent. The main model uses its normal `read` tool.
- A topic-to-file table acts as the router. It costs about 300 tokens each turn.
- Caveat: the Pi checkout in my memory notes is at v1.0.1, so line numbers may differ from the pinned commit used in the Ask roadmap.

## C. Other harnesses

- Gemini CLI has the closest equivalent to Claude's guide agent. `packages/core/src/agents/cli-help-agent.ts` defines a "cli help" agent with one tool, `get_internal_docs`. Its prompt says to call the tool with no argument to list docs, then fetch the file it needs. `packages/core/src/tools/get-internal-docs.ts` finds the bundled `docs/` folder by walking up to a folder that holds `sidebar.json`. It rejects paths that leave that folder (path-traversal guard). Docs ship in the package, as in Pi.
- Codex CLI: I found only the AGENTS.md convention for project instructions. I did not find a self-documentation mechanism in the model prompt. Unverified; I did not read the Codex prompt files.
- OpenCode: built-in agents are Build, Plan, General and Explore. Prompts are chosen per provider. I found no self-help agent. Unverified; the search results were docs pages only.

## D. Keeping docs current

| Pattern | Example found | Trade-off |
|---|---|---|
| Generate reference docs from code, and fail CI on diff | Gemini CLI: `npm run docs:settings` and `docs:keybindings` run `scripts/generate-*-doc.ts`. The CI lint job runs `npm run docs:settings -- --check`. | Deterministic and cheap. It covers only what a registry describes (settings, keys, tools). It gives no prose. |
| Generate schemas from types | Codex `justfile`: `write-config-schema`, `write-app-server-schema`, `write-hooks-schema`. I did not see a matching check in the justfile. I could not fetch its CI file (404), so drift enforcement is unconfirmed. | Types stay the source of truth. Without a CI check, drift only shows at the next regeneration. |
| Auto-generated index | The Claude Code docs map is generated by GitHub Actions, with a timestamp. | A doc index never drifts from the pages. |
| Ship docs inside the package | Pi and Gemini CLI. | The model sees docs that match the binary. This costs package size and needs a release to fix a typo. |
| CI agent on PR | `anthropics/claude-code-action@v1` takes a `prompt` and runs on `pull_request: [opened, synchronize, reopened]`. The sample prompt asks for "security issues and documentation gaps". | Catches prose drift. It costs tokens on every push, can be noisy or wrong, and needs a human to merge. Prefer report mode (a comment) over auto-commit. |
| Claude Code hooks | `Stop` and `PostToolUse` hooks run shell commands, prompt hooks, or experimental agent hooks. A Stop hook can block and ask the model to continue. Claude Code overrides a Stop hook after 8 blocks in a row with no tool call in between, so the script must check `stop_hook_active`. | Local and immediate. A Stop hook that always demands doc updates burns turns. Use it to run the generator and check, not to ask the model to judge. |
| Docs-update skill or agent after implementation | A workflow step, not a CI step. This is the repo-local rule: update docs only when behavior, commands, config or architecture changed. | Handles prose and cross-links. It depends on the model remembering, so back it with the CI check above. |

## Recommendation for Ask (ranked)

1. Pi pattern first: a short "Ask documentation" block in the system prompt with runtime-resolved paths (embedded `docs/` or on-disk path) and a topic-to-file table. Cheapest and offline. It fits the Go single binary; use `go:embed` for the docs.
2. Gemini CLI pattern second: if Ask has subagents, add a `get_internal_docs`-style read-only tool plus a small help agent. This keeps docs out of the main context. Do this only when the docs outgrow the Pi-style table.
3. Docs drift: generate the tool list, slash commands, settings and flags into markdown from the registries. Add a `--check` step to CI, the way Gemini CLI does. Add a Stop or PR-time agent only for prose, in comment-only mode.
4. Skip the Claude-style fetch-from-web docs map unless Ask hosts docs online. It needs network and fails offline.

## Limitations

- I read no Claude Code source. Its prompt wording comes from Piebald's third-party extraction, and the environment block and feature lists come from this session's own prompt.
- Codex and OpenCode self-knowledge were not verified in source.
- Codex drift enforcement could not be checked (CI file 404).
- I did not check that update-config and keybindings-help skills have public docs.

## Unresolved questions

- Does Ask ship docs inside the binary, or read them from a path on disk?
- Does Ask have a subagent runtime today, or only the main loop? The answer decides between recommendation 1 and 2.
