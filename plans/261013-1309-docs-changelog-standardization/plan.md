# Standardize docs and changelog (open-source layout) with an update flow

Status: phases 1-6 done 2026-10-13 (user approved the plan and its four defaults on 2026-10-13). CI, LICENSE, tagging still open.
Branch: `agent-capability-discovery-autodoc`.
Research: `plans/reports/researcher-261013-1258-agent-self-knowledge.md`.

## Outcome

Ask has the document set that a typical open-source Go project has, every
document tells the truth about the current code, and a repeatable flow keeps
them true after each change:

- registry-backed reference docs are generated from code and `go test` fails on drift;
- prose docs and `CHANGELOG.md` are updated by a project skill after each feature.

Agent self-knowledge (system prompt block, `ask-self` skill) is out of scope
here. It comes next and reuses the reference docs that this plan generates.

- `AGENTS.md` and `CLAUDE.md` are two copies that drifted (testing list, ACP and

- Commits: conventional style since `feat(auth)` (about 20 of 43 commits); older ones are free text; no tags.
- Sources of truth in code: tool registry (`cmd/tui/headless.go:233` `sessionTools`,
  `internal/tools/prompt.go` snippets), provider catalog (`internal/providers/catalog.go`),
  CLI subcommands (`cmd/tui`), `ask version --json` (`cmd/tui/version.go`).

## Target layout

```
README.md            what Ask is, install, quick start, links (user-facing)
CHANGELOG.md         Keep a Changelog 1.1.0 format, [Unreleased] on top
CONTRIBUTING.md      setup, tests, lint, commit convention, docs rules, changelog rule
LICENSE              (user decision)
SECURITY.md          how to report a vulnerability (optional, user decision)
AGENTS.md            single source of agent instructions
CLAUDE.md            one line `@AGENTS.md` (Claude Code import) so the two cannot drift
docs/
  README.md          NEW index: what each doc is for and who reads it
  reference/         NEW, GENERATED: tools.md, providers.md (do not edit by hand)
  cli.md             NEW, hand-written: ask subcommands and flags
  existing files     stay in place (no moves by default; links in plans, memory
                     and 45 package READMEs point at them). A guides/ + architecture/
                     reorganization is an option only if the user asks.
```

CHANGELOG.md and CONTRIBUTING.md go at the repo root because that is the
open-source convention the user asked for on 2026-10-13.

Package `README.md` files stay where they are (dewee rule: one owner README per package).
