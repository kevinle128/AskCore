## Decisions these findings add for the user

Resolved by D25 (follow DeepSeek by default): retry numbers follow DeepSeek with no jitter (D11) and Pi `auto_retry_*` events derived from the durable retry record; tool default mode follows DeepSeek; `Subscribe` stays synchronous with contained listener failures; credential failure stays an assistant error message, and the commit timing is user question Q8.

The plan already has questions Q1 to Q7. The findings add these decisions:

- Retry numbers and event family: DeepSeek (5 retries, 500 ms base, 10 s cap, jitter, durable retry entries, budget per provider) or Pi (3 retries, 2 s base, no jitter, `auto_retry_*` events). Finding 9.
- Tool default mode: DeepSeek (alone unless declared safe for these arguments) or current Ask (parallel unless `Sequential()`). Finding 10.
- `Subscribe` contract: stay synchronous or become asynchronous with `Flush`. Finding 2.
- Credential failure before dispatch: assistant error message (current) or Run error with nothing committed (DeepSeek). Finding 4.


## Revision after the source audit (2026-10-06)

Finding 15, part "bounded abort drain then outcome-unknown", is withdrawn. It reversed D19, which requires started bodies to drain before the Step closes. DeepSeek (`tool-calls.ts:233`) and Pi (`A:agent-loop.ts:646`) both wait without a bound. The user reaffirmed D19 on 2026-10-06 (option A). Source: `plans/reports/review-261006-1104-deepseek-lifecycle-source-audit.md`, finding 1.

Finding 14: the bounds stay, but their status changes from "Ask new" to `diverge-deliberate` (BOUNDS). A bounded ring, follower buffer and queue change what an upstream run or caller observes (`resync`, `ErrQueueFull`), and the source audit ("Report precedence") reserves "Ask new" for added capability. Finding 14's "stored truncated in the ring" detail is replaced by a gap marker plus `resync` (source audit, phase 05 correction).
